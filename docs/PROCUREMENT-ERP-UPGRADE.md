# 采购履约与 ERP 纠错闭环大任务

目标：在现有单公司系统上，完成采购发生变更时的真实处理，所有操作在手机和桌面可用。保留现有源码、业务数据和 V1–V4 迁移；不引入多租户、通用 BPM 或真实银行操作。

## 里程碑与验收

- [x] M1 订单收尾：未收货取消、部分到货后关闭剩余数量；保留原因、操作人和时间。关闭/取消后按未履行数量生成一次可追溯的新申请草稿，重新走审批，防止重复补采。
- [x] M2 项目退料：关联原领料流水，可分次退回原仓；累计数量和金额不能超过原记录，最后一笔吸收分币尾差。增加库存、冲减项目材料消耗；不改变采购应付和现金。
- [x] M3 采购退货：关联原入库明细，检查原可退量与仓库现存量；扣减库存和应付，保留原入库。原单价与当前移动加权库存价值有差额时，单独记录项目计价差额，避免负库存或篡改旧流水。
- [x] M4 供应商退款：退货后若净实付超过净应付，展示待收退款；财务登记部分退款及唯一凭证，限制超额/重复退款。原付款及批准申请保持历史记录。
- [x] M5 追溯与操作：订单详情展示收货、关闭、退货、退款、补采申请；库存页面可查领料及退料，财务页面区分应付未付与待收退款；全部复用响应式布局和权限校验。
- [x] M6 交付验收：H2 业务测试、真实 MySQL 迁移/HTTP/并发、账实 SQL、手机及桌面关键操作、Compose 和重启保留数据，更新接口与操作文档。

## 数量和金额规则

- 原申请、订单、入库、领料、付款不删除、不改写为纠正后金额；更正通过新记录留痕。
- 原采购单保持原始数量/总额；关闭剩余数量、金额另列，净采购订单额扣除关闭部分及采购退货冲减。已入库应付不因订单关闭而改变。
- 项目退料按原领料实际金额分摊，不使用当前市场价或采购报价；退回原仓后重新计算库存均价。
- 采购退货应付冲减按原入库金额分摊；库存出库价值按当前移动加权计价，差额另列为自动计价调整，不伪装为项目材料领料。
- 退货不能侵占待审批/已批准付款申请占用；冲突时先撤回相关申请，再退货。
- 应付以验收入库减采购退货确认；净实付以付款减供应商退款确认。退货形成待收退款可以暂时高于净应付，普通付款仍不能制造超付。
- 数量 3 位、单价 4 位、金额 2 位，计算和校验全部在服务端；多行操作事务化，保持统一锁顺序和唯一凭证约束。

本轮按上述范围执行，实际结果见下文。移动端的独立验收记录见 [MOBILE.md](MOBILE.md)。各阶段完成后在本文件补充实际结果，不以计划代替实现。

## 本轮已完成与实际验收

2026-10-21 已完成 M1–M6。新增 V5 为增量迁移，保留 V1–V4 校验和；既有业务金额不回填、不重写。

### 操作入口

- 采购订单详情：采购人员可取消未收货订单、关闭部分收货订单的剩余采购；有采购申请写权限的项目人员可生成一次补采草稿，并追溯原订单。补采需要独立提交审批。
- 库存与领料 → 领料与退料：选择原领料单，按可退数量办理原仓退料；在退料记录中查看成本冲回及凭证。
- 订单详情 → 验收与退货：选择原入库单办理采购退货；退货记录同时展示应付冲减、库存冲减和计价差额。
- 应付与付款：查看退货后应付、净实付、累计退款和待收退款；财务登记实际到账的供应商退款，支持部分退款。
- 订单详情：集中查看原数量、已收、已退、已关闭、待收、退货、原付款、退款、补采关联和操作追溯。手机使用卡片及纵向表单，桌面保留表格。
- 无权限页面的“切换账号”会注销当前会话后进入登录页。

### 汇总口径

原订单金额、原入库单、原领料单和原付款记录保留。净采购订单额按原金额扣除关闭金额及采购退货冲减；待收数量按原数量扣除已收及已关闭数量，退货不自动重开原订单。项目材料成本按领用减项目退料计算；退货计价差额单独列入自动费用调整。净实付按原付款减实际供应商退款计算，应付未付与待收退款分别非负展示。

不同采购价的同仓材料使用移动加权计价。采购退货的原入库冲减可能不同于库存出库价值，差额以 `RETURN_VARIANCE` 单独记录，允许正负；看板遇到负成本构成改用条形图，保留其符号。它是当前简化 ERP 的计价规则，不替代完整总账、期间结账或客户专属会计政策。

### 仍保留的范围边界

退回原仓，不处理跨仓调拨；采购退货不自动补发或重开原订单。订单关闭/退货不自动改写合同金额，合同变更需单独修订，合同金额差不能替代应付余额。退款是到账记账，不连接银行；未实现税票红冲、通用付款冲销、完整总账、多级退货审批或多租户。手机证据为浏览器设备模拟，未宣称真机 Safari/Android 及软键盘测试已完成。
