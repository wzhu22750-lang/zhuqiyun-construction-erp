
## 现场操作：钢筋采购到项目成本

建议先用 admin 在“仓库管理”创建独立演示仓库，保证该材料期初库存为零，便于核对移动加权成本。供应商选择合作中且资质有效的两家。每轮使用不同的到货、领料、付款参考号。

| 步骤 | 角色与页面操作 | 可核对的结果 |
| --- | --- | --- |
| 1 | manager 登录；采购申请 → 新建，选择滨江商务中心，添加钢筋材料（规格来自材料档案），数量 10、预估单价 3600，填写需求日期 | 草稿申请金额 36,000.00 元，后端保存多行明细 |
| 2 | 申请详情提交审批 | 状态变为待审批；未通过审批不能下单 |
| 3 | 退出后以 boss 登录；审批中心打开该申请，填写意见并通过 | 保存审批人、时间、结果和意见，申请状态已批准 |
| 4 | buyer 登录；询价与比价打开该申请，录入两家供应商报价，单价分别 3500、3550，交期 3、5 天 | 比较总额 35,000.00 / 35,500.00 元及交期 |
| 5 | 选择第一家报价，填写“同规格价格较低、交期更短”等中标原因并生成订单 | 订单 35,000.00 元；同一申请不能再次授予 |
| 6 | warehouse 登录；采购订单详情选择独立仓库、填写到货参考号、质检说明，本次验收 6 | 原子完成验收和入库，订单部分到货，库存 6，入库金额及应付均为 21,000.00 元 |
| 7 | 库存与领料选择同仓库、同钢筋、滨江项目，领料 2，填写唯一参考号 | 库存剩余 4，项目新增材料成本 7,000.00 元，出库流水可追溯 |
| 8a | finance 登录；应付与付款找到对应订单，申请付款 10,000 | 申请待审批，占用 10,000，可申请余额变为 11,000；尚未形成实际付款 |
| 8b | boss 登录；应付与付款 → 付款申请，审核并批准 | 状态已批准待付款，记录审批意见及人员 |
| 8c | finance 登录；执行该已批准申请，填写唯一付款参考号 | 已付 10,000.00 元、待付 11,000.00 元；申请操作记录保留提交、批准和付款 |
| 9 | boss 登录；项目详情查看申请、订单、入库、领料、付款五种口径 | 对比演示前快照：分别增加 36,000 / 35,000 / 21,000 / 7,000 / 10,000 元 |
| 10 | 返回经营驾驶舱刷新 | 汇总从数据库重新计算；采购额、实际成本和待付款按各自业务口径变化 |

项目详情同时提供概览、进度记录、采购申请、采购订单、成本明细和关联合同。项目列表可维护项目基本资料；未关联业务的项目可以删除，已有业务的项目受后端关联保护。

如果使用已有库存的仓库，领料金额按该仓库该材料的移动加权平均成本确定，可能不同于本单 3500 元单价。请以服务端领料记录为准。当前验收与入库为合并事务，付款登记不连接真实银行。

## 数据口径与功能边界

- 申请为预估需求；订单为采购承诺；入库为已验收物料价值并生成应付；领料为项目材料消耗；付款为资金登记。只有领料材料成本与已登记的其他费用构成当前项目实际成本，不把五种金额相加。
- 看板年度合同总额按项目 `start_date` 属于所选自然年度汇总，并非按合同签订日期；其他指标各自为累计或当前状态口径。
- 采购为简化单级审批和整单单供应商授予，一条申请一张订单；关闭或取消后可生成新补采申请。已支持项目退料、采购退货与退款，尚无拆单、税票红冲、调拨和独立质检流程。
- 付款申请占用余额，经单级独立审批后只能执行一次，支持驳回及撤回；未实现多级付款审批、银行支付或总账。合同付款计划可维护，尚不自动分期执行；工程回款与分包付款没有独立核算。
- 当前单公司、每账号单角色；tenant_id=1 仅为扩展点，未完成租户隔离、开户、计费。经理按负责人限制项目；尚无复杂组织数据范围。
- 公司名称、系统名、主题可配置；Logo 上传、原生 App/小程序、BIM、电子签章、企业微信及高级报表未实现。
- MySQL 启动中 Flyway 对 performance_schema 的探测可能有非致命权限提示，迁移与业务访问已通过；没有为消除提示扩大业务账号权限。
- 依赖版本、原文和分发缺口见 [许可证清单](DEPENDENCIES.md)。包括两项 MIT 原文未齐、MariaDB LGPL 的对应源码/替换或重新链接交付方案、镜像与其他受限组件的分发义务；尚不能视为闭源商业交付合规已完成。
- 生产部署仍需具体客户环境的 TLS、备份恢复、监控告警、安全审计和容量验证。本 Demo 的运行与测试证据不代表这些工作已经完成。
